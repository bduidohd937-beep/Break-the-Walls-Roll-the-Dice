# 성벽을 부수고 주사위를 던져라

React + TypeScript + Vite로 만든 2D 횡스크롤 자동 전투, 영지 경영, 영웅 수집 **프로토타입**입니다. 현재 이모지와 성·배경 도형은 임시 그래픽입니다.

## 로컬 실행

```powershell
npm install
npm run dev
npm run build
```

## 현재 구현 범위

- 왼쪽 아군 성에서 영웅을 반복 출격시켜 오른쪽 적 성을 공략합니다. 최대 10명 편성, 전장 아군 최대 50명, 전투 UI는 5명씩 페이지로 표시합니다.
- Battle Gold는 전투에서만 사용합니다. Game Gold는 영지와 영웅 성장에, Gem은 영웅 소환에 사용합니다.
- 소환 10+1은 11회이며 결과는 저장소로 이동합니다. `???` 등급은 일반 소환에서 나오지 않습니다.
- 영지 시설, 자동 채집과 최대 8시간 오프라인 생산, 스테이지 1~50 기본 구조, 보스 전투, 첫 클리어와 반복 보상이 들어 있습니다.
- 스테이지 일반 데이터, 성장·보상 수치, 영웅 구성, 합성 레시피는 대부분 임시입니다. 합성소에서 현재 실제 영웅을 지급하는 레시피는 손오공뿐이며 다른 레시피는 준비 중입니다.
- 9스테이지 기간토스는 전용 적 엔티티로 등장하지만 세부 전투 능력치는 임시입니다.

## 개발자 테스트

로컬 개발 서버는 기본적으로 개발자 데이터 프로필을 사용합니다. 일반 프로필 테스트는 `?dev=0`을 붙여 엽니다. 배포 빌드에서는 `?dev=1`을 붙여도 개발자 기능이 켜지지 않습니다. 개발 서버와 일반 프로필은 서로 다른 localStorage 키에 저장됩니다. 브라우저에서 localStorage를 지우면 해당 출처의 저장 데이터가 사라집니다.

기본 회귀 확인: 첫 클리어·재클리어 보상, 9·20·30·40·50 보스 등장 및 처치, AUTO COM, 편성·소환·저장소·합성, 재접속 후 저장 유지.

## Phase 1-3 — 세렌티아 기본 유닛 추가

- 차원술사 세렌티아를 전설 등급 원거리 단일 공격 영웅으로 추가했습니다. 특수 스킬·상태이상·광역 공격은 아직 없습니다.
- 제공받은 정면 PNG와 걷기·공격 GIF를 사용합니다. 전투에서 이동할 때는 걷기, 기본 공격할 때는 공격 애니메이션이 재생됩니다.
- 세렌티아는 기존 저장 데이터를 포함해 보유 영웅으로 자동 지급됩니다. 출전 편성에서 추가하면 첫 전투의 시작 Battle Gold 300으로 바로 출전할 수 있도록 비용은 280으로 설정했습니다.
- `UNIT_ANIMATED_SPRITES`는 정면·걷기·공격 자산을 단위별로 분리합니다. 이후 세렌티아의 스킬 시전·피격·사망 애니메이션을 여기에 추가해 전투 데이터와 분리하여 연결할 수 있습니다.

검증: 프로덕션 빌드와 diff 검사 통과. 기존 저장 프로필에서 세렌티아 자동 보유, 영웅 상세의 기본 공격 표시, 편성 추가·저장, 전투 출전 및 전용 스프라이트 렌더링을 확인했고 브라우저 오류는 없었습니다.

## Phase 1-4 — 세렌티아 전투 스프라이트 정렬

- 원본 걷기·공격 시트의 각 프레임에서 투명 여백을 잘라 공통 발선과 캐릭터 높이에 맞춘 12프레임 PNG 시트를 생성했습니다. 원본 파일은 변경하지 않았습니다.
- 정지·걷기·공격 이미지가 같은 크기의 투명 프레임을 사용해 전투 중 캐릭터 크기와 바닥 위치가 유지됩니다.
- 공격 모션 진행 시간을 공격 간격과 전투 배속에 연동하고, 전투를 멈추면 CSS 프레임 애니메이션도 멈춥니다. 기존 영웅의 공격 표시 타이밍은 유지합니다.
- 빌드 통과. 화면 확인에서 세렌티아 크기·발선과 1배속 / 5배속 애니메이션 시간(각 공격 간격 1.55초 / 0.31초)을 확인했습니다.

## Phase 1-1 — 허브 메뉴 이동 안정화

- 기준: main `2a1d58c`.
- App.tsx의 공통 메뉴 이동 처리로 허브 이동 콜백을 통일했습니다.
- 소환 연출 중 메뉴 이동을 차단하고 왕국 복귀 버튼도 비활성화합니다.
- 출전 진입 시 로비 선택과 편성창을 초기화합니다. 영웅 진입은 보유 영웅 화면으로, 소환 진입은 안내 메시지를 초기화합니다.
- 전투·성장·보상·덱 저장 로직은 변경하지 않았습니다.

검증: 프로덕션 빌드와 diff 검사 통과. 별도 브라우저 테스트 프로필에서 출전 로비 초기화, 영웅 탭 편성 변경 및 새로고침 후 유지, 소환 중 메뉴 이동 차단, 영웅 공개 후 SKIP 및 정상 공개 완료 후 이동을 확인했습니다. 해당 시나리오에서 브라우저 실행 오류는 없었습니다.

Phase 1-1 당시 발견 (아래 Phase 1-1b에서 해결): 소환 시작 직후 SKIP하면 기존 setTimeout이 연출 상태를 다시 변경하여 메뉴가 잠기는 문제가 재현됩니다. 기존 소환 컨트롤러의 타이머 취소 처리가 필요하며 별도 승인 후 수정합니다. KINGDOM 내부 onBattle 콜백은 현재 화면에서 사용하지 않습니다.

다음 후보: 소환 조기 SKIP 타이머 정리 승인 → KINGDOM 레이아웃·스크롤 검증 → 편성 두 진입 경로 상세 검증 → 픽셀 에셋 교체 구조 정리.


## Phase 1-1b — 소환 SKIP 타이머 안정화

- 소환 연출의 예약 타이머를 보관하고 SKIP·정상 완료·다음 소환 시작·컨트롤러 해제 시 정리합니다.
- SKIP 이후 이전 연출이 다시 실행되어 메뉴가 잠기는 문제를 수정했습니다.
- 소환 확률, 비용, 천장, 지급 및 저장 로직은 변경하지 않았습니다.
- 변경 파일: src/game/controllers/useSummonController.ts, README.md.

검증: 프로덕션 빌드 및 diff 검사 통과. 별도 일반 프로필 브라우저에서 throw·impact·crack 각 단계 SKIP 후 2.1초가 지나도 연출이 재개되지 않고 메뉴를 이동할 수 있음을 확인했습니다. 즉시 SKIP 후 다음 소환 정상 완료, 10+1의 11명 정상 공개, 총 1,500 Gem 차감 및 결과 16개의 고유 저장, 새로고침 후 결과 유지가 통과했습니다. 브라우저 실행 오류는 없었습니다.

다음 작업: KINGDOM 화면 겹침·스크롤·해상도 대응을 먼저 점검하고, 발견한 문제의 변경 파일·위험·검증 계획을 정리하여 적용 전에 승인받습니다.

## Phase 1-2 — KINGDOM 모바일 배치 안정화

- HUD가 세로 공간 부족으로 축소되지 않도록 하여, 재화·설정 영역이 줄바꿈되어도 지도와 겹치지 않게 했습니다.
- 800px 이하에서는 금고·훈련소를 위쪽, 벌목장·채석장을 아래쪽으로 배치하여 중앙 성과 클릭 영역을 분리했습니다.
- 변경 파일: src/styles.css, README.md. 게임 로직과 버튼 기능은 변경하지 않았습니다.

검증: 빌드와 diff 검사 통과. 1440×900, 768×1024, 390×844, 320×568, 844×390에서 왕국·목표·시설 화면의 가로 넘침, 시설 영역 겹침이 없고 끝까지 스크롤하면 마지막 내용에 접근 가능함을 확인했습니다. 320px HUD 높이는 78px에서 108px로 늘어나 재화 영역을 포함합니다. 추가로 320·390·480·481·768·800·801·844·1440px 너비에서 다섯 시설의 이동 목적지와 설정 열기·닫기를 확인했고 브라우저 실행 오류는 없었습니다. 모바일·태블릿 스크린샷도 검토했습니다. 검증은 데스크톱 Edge의 화면 크기 변경 환경에서 수행했으며 실제 모바일 기기 검증은 포함하지 않습니다.

다음 작업: 영웅 탭 및 출전 로비의 편성 진입·슬롯 변경·페이지 전환·저장 유지 상세 점검. 수정이 필요한 경우 적용 전에 범위와 위험 요소를 정리하여 승인받습니다.
